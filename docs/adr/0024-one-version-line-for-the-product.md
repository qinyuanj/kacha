# 产品版本号只有一条线

2026-11-16 决定（[版本号回到一条线：接续 1.4.x 进 1.5.0，桌面不再另起号](https://github.com/qinyuanj/kacha/issues/141)）：Kacha 只有一个产品版本号，接在 1.4.x 后面，本次一起进 **1.5.0**。桌面客户端不是第二个产品，它是接在 1.4.0 后面的下一版；版本号只由两张清单声明——服务端清单 `server/Cargo.toml` 与桌面配置 `mygo.config.ts`，两者必须同号。

漂移的经过与代价：提交 `e2b3c1e` 把桌面配置从 `0.1.0` 提到 `0.2.0`，而同一个号码更早的旧桌面版已经用过一次，于是同一个号指着两个不同产品。美术每天用的是浏览器里的 1.4.0，新桌面客户端的顶栏却写 0.2.0——比每天在用的那版还「小」；「更新内容」里没有任何一段被标成当前版本，最上面那段讲的还是 1.4.0 的变化。维护者没法从界面上看出这一版接在哪一版后面，「改了版本号却忘了写更新说明」也没有任何东西拦得住。

规则：

- **两张清单同号**。`packaging/release_gate.py` 的 `check_version_line(root)` 读两边，不同号就以中文原因退出并说清两边各是什么；仓库级守护测试（`client/src/core/changelog.test.ts`）断言更新说明里与当前版本同号的一节、服务端清单、桌面配置三处一致，失败信息指出是哪一处。
- **更新说明是产品级文档**（`docs/release/web-changelog.md`，界面「更新内容」的唯一来源），讲这一条版本线，不分网页版与桌面版。书写格式不变：一级标题只放版本号、新在前不重复、二级标题只用「新增 / 改进 / 修复」、改变操作习惯的条目以「注意：」开头；当前版本那一节「新增 / 改进 / 修复」下至少一条条目。
- **门禁只有一份**。`check_release_notes(root, version)` 与 `check_version_line(root)` 定义在 `packaging/release_gate.py`，web 与桌面两个构建入口都 import 它：缺更新说明或两张清单不同号都以中文原因拒绝构建、退出码非零、不跑任何构建命令。
- **改版本号只动两张清单**，再在更新说明最上面加一节。
- **内部构建号**：已经构建过、但从没对外发布、也没打 tag 的桌面 `0.1.0` / `0.2.0` 记为内部构建号——不补 tag、不给它们补更新说明的一节，只在决策记录里交代。退役版本（`0.2.x` / `0.3.x`）的发布说明原样保留。

## Considered Options

- **分制品两条线（web 一条、桌面一条，各自从自己的号往下走）**：否决。产品只有一个，人在两边之间转移；两串号码无法比较先后，换到桌面客户端会以为退回了旧版本——这正是这次漂移的表现。
- **收敛成单一版本文件作为唯一来源**：否决。Cargo 清单与 MyGo 配置各自必须声明版本，抽第三个文件只多一层间接，还得再解释「谁是真正的那份」。要的是同号，不是一个新格式；一致性交给门禁与守护测试，比多一个文件更早报错。
- **只改桌面配置、服务端留在 1.4.0**：否决。顶栏（读 `server/Cargo.toml`）与桌面（读 `mygo.config.ts`）仍是两个数，只是把更大的号码给了桌面，问题原样保留。
- **靠人工记得两边一起改**：否决。漂移已经发生过一次；能机械发现的事不该靠记性。

## Consequences

- 发布纪律：1.5.0 的 web 构建与桌面客户端同一批发布；在那之前部署机继续跑 1.4.0（见 [packaging/README.md](../../packaging/README.md)）。
- 版本号有两条显示链路，改号时要清楚它们各自读什么：web 顶栏读服务端配置接口返回的服务端版本，既有端到端断言就在比对顶栏与 crate 清单，改号会自动跟随；桌面顶栏读打包时写进可执行文件的版本资源，源码里运行退回 `dev`——所以「顶栏显示 1.5.0」只能用打包产物验收。
- 别拿别的号来「对齐」：画板格式号、画板包格式号、包清单里的应用版本、构建工具版本（MyGo、Go）各自独立，都不随产品版本号变（见 [GLOSSARY.md](../../GLOSSARY.md) 的「版本号」）。
- 质量工具的变异工作副本要读到版本来源：`MUTATION_COPIES` 增加 `../mygo.config.ts`，否则改动了包内文件的基线测试在副本里读不到桌面配置而失败。
- 不自动打 tag、不做自动发版流水线；本决定只保证人手改动时不会漂。
