# 删除反馈中继，桌面直连 Gitea

现有版本已经让用户通过本机 OAuth 授权自带 Gitea token，但桌面仍把 token 和反馈交给 `lzxsvn:3005` 中转。继续维护中继服务、部署脚本和独立 exe 只增加运维面，没有提供用户直连无法替代的能力。

## 决定

- 保留反馈、一键授权、DPAPI 凭据保护、附件和本机诊断导出；桌面 Go 服务直接调用同一 Gitea 的 `qinyuanj/kacha-feedback`，不再设置任何中继地址或回退路径。
- 删除中继 Go 服务、命令入口、部署脚本以及 debug/release 构建与发布规则；删除 Gitea 历史 Release 中的中继 exe，并同步移除 `SHA256SUMS` 条目。桌面安装器、签名、更新描述、Release、tag 和已有反馈 issues 保留。
- 停止并删除 `lzxsvn` 上的 `kacha-feedbackrelay` Windows 服务及其实际部署 exe，但保留 Gitea、OAuth 应用和反馈仓库。服务删除需要管理员会话，未核实前不得声称完成。
- 旧设置里的 `feedback_relay_url` 无论值是什么都在读取时丢弃，避免未知字段保留机制把它再次写回；其他设置不变。
- 本机内存保留两分钟重复提交识别，避免双击或立即重试重复建单；不再维持中继的按 IP 限流。

## 考虑过的方案

保留中继兼容旧客户端会让服务、发布资产和 token 转发面继续存在，与彻底删除的目标冲突。删除整个反馈入口则会丢掉仍被使用的排障能力，因此也不采用。

## 后果

中继服务下线后，旧版客户端的反馈会明确失败，不提供兼容中继；本机画板、任务目录、数据管理和新版直连反馈不受影响。历史发布资产被清理后不能再用于重新部署中继，这是有意提高恢复成本的决定。产品版本进入 1.7.3，但该版本还承载其他改进，本次不单独构建或发布。
