# 任务运行器在核心内管理时序与画板归属

运行器接收文件、网络、时钟、日志和画板系统变更端口，对外提供提交、重新生成、取消、并发设置与快照订阅。每个任务显式记录读图、等待、退避与执行状态；快照按画板和任务节点聚合，内部任务按提交编号区分，避免同一画板包重复导入后串状态与锁定。

输入、模型、网关配置和数据根在提交时固化；派发时才写任务目录与提交记录，退避不重写。任务目录已写才记录失败或取消。关闭画板后遗忘该画板的内存状态，重开从任务目录恢复结局，无结果也无结局记录即已中断。

Flash 拒绝、坏响应或下载失败直接失败，不自动重发或换模型；其他模型保留既有 429 退避。取消只代表客户端停止等待和落结果，不代表网关计算已停止。每份各自成败，不自动补跑失败份。

跨异步调用的时序是模块职责，由运行器公开接口验证，不把多份状态放回 UI 维护。桌面生成端口自 #153 起接通：份数、跨画板的唯一队列、逐份取消与 429 退避都由这一个运行器执行（#155）。

快照上的 `activity` 就是忙闲判断：读图、排队、执行、退避的份数与涉及的画板，数据根迁移与更新准备读同一份，不另建任务状态。退避只是那一份在等重试，最后一份退避的份被取消后整条队列立即恢复派发，不连累别的任务。
