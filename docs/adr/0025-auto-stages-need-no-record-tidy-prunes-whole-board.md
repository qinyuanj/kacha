# 自动划分阶段不记「已划分过」，整理可以整板一次收掉

2026-11-16 决定（[自动划分阶段：把画板按生成尝试划成阶段，并一次收掉整板未定稿](https://github.com/qinyuanj/kacha/issues/142)）：这次收敛下来的两个反直觉决定写在这里，免得后来的人从代码里反推。

**自动划分阶段只作用于还没进阶段的节点，所以重复执行天然是空操作。** 划分的候选集合是「本版本认识的、且不在任何阶段里的节点」，按一次生成尝试（生成任务节点 + 该任务的结果列〔任务指向结果的系统连线，列内成员按结果节点上相同的 `task_id` 取全〕+ 直接连线喂给它的提示词与参考图）聚成单位，成员少于两个的不建阶段。结果归属靠系统连线、不靠 id 相等：结果节点上的 `task_id` 是服务端的提交编号，不是任务节点 id；列内成员先由任务指向结果的系统连线归到任务，再按相同的 `task_id` 取全——写成「`task_id` 等于任务节点 id」就一个结果都认不到。已经进过阶段的节点一概不碰——于是「再点一次只把之后新长出来的尝试补进去」不需要记住上次划到哪里，它是筛选条件的直接结果。我们因此**不引入**「这块画板已经划分过」的记录，也不新增界面状态字段：那条记录唯一剩下的效果是拦住自动划分之后新长出来的尝试，而那正是用户再点一次想得到的。同样，「没有候选时不留撤销步」也不是额外规则——变更只表达意图，算不出要动的东西就返回原画板（与「收掉未定稿」同形，见 [ADR 0014](0014-board-changes-are-a-closed-union-behind-one-entry.md)），画板没变就没有撤销步。

**整理模式的破坏性动作可以整板一次执行。** 整理条上的「收掉整板未定稿（N）」等价于一次「收掉未定稿」传全部阶段 id：现有变更已经接受阶段 id 数组，核心零改动，N 与确认框里的数字仍由既有判定现算。它**放松**了 [整理模式与「收掉未定稿」](https://github.com/qinyuanj/kacha/issues/92) 定下的「逐阶段手工收掉」交互——仍是一次点击 + 一次确认 + 一步撤销，只是作用面从单个阶段扩到整块画板；逐阶段的「收掉未定稿」原样保留，作为细粒度选择。这不是悄悄推翻 #92：那条要防的是「不经确认就删」与「删了还不回来」，两者都还在。体量提醒与越线提示条（[#87](https://github.com/qinyuanj/kacha/issues/87)）、「移出为新画板」（[#93](https://github.com/qinyuanj/kacha/issues/93)）都不受影响：体量档位只驱动提示条，不改变整理模式给哪些动作。

## Considered Options

- **记一条「这块画板已经划分过」，或给界面加一个「已划分」状态**：否决。见上：筛选条件已经让它天然幂等，记录多出来的唯一效果是拦住后来的新尝试；它还得按画板路径键控，跟着画板改名走。
- **进入整理模式时自动划分**：否决。点「整理」是查看，查看不该写画板；越线提示条那条入口也不该顺手改画板。划分做成整理条上的按钮，点了才写。
- **整理模式只保留逐阶段收掉，不做整板**：否决。自动划分之后阶段可能二十个，逐阶段点二十次等于把「一次减掉」这一步又还给了用户。
- **整板收掉另起一种画板变更种类**：否决。现有「收掉未定稿」已接受阶段 id 数组，传全部 id 就是整板，核心不需要改；多一种变更是纯增的负担。

## Consequences

- 重复点击、以及「画板上没什么可划」都不产生撤销步，这是 [ADR 0014](0014-board-changes-are-a-closed-union-behind-one-entry.md) 既有结构的自然结果，不为它另写规则。
- 撤销步描述形如「自动划分 3 个阶段」，一次点击一步，不设归并键。
- 划分只写结构（阶段），不写定稿、不删节点；破坏性动作仍由用户点击触发。
- 已归档 / 只读画板照旧拒绝写入，沿用只读语义，不为此加特例；度量暂时不可用只让体量数字显示为「…」，不影响划分与按钮可用性。
- 整板收掉的确认框与逐阶段那条共用一套文案构造：总张数、画板约减少多少、其中几张是建议保留（词见 [GLOSSARY.md](../../GLOSSARY.md) 的「建议保留」）。
- 已知代价：阶段数可能偏多（一次尝试一个阶段）。真实画板上出现二十个以上阶段、或「一个任务一个框」看着比不整理还乱时，改成「按上游结果合并相邻尝试」——那时起作用的是同一层筛选条件，只是划分单位变了。
