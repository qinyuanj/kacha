# 反馈是可选的联网能力

Kacha 的画板核心保持单机优先：打开、编辑、组织和打包画板都不需要网络。反馈是用户主动发起的可选联网能力，不参与画板核心路径。

## 决定

- 用户从首屏「反馈」入口提交文字、可选截图与脱敏诊断包；反馈中继只负责把这些内容转发到 Gitea `kacha-feedback` 仓库并回传 issue 编号与链接。
- 反馈中继内置地址是 `http://lzxsvn:3005`，高级设置可以覆盖；留空或无效值回退默认值。该地址只用于本次反馈发送。
- 不新增远端应用服务依赖：客户端启动、画板编辑与本机数据管理都不调用反馈中继，也不要求用户登录远端服务。反馈不可用时，核心画板必须继续离线可用。
- 反馈内容不进入画板、任务目录或画板包；诊断包沿用脱敏规则，不携带 API 密钥、网关密钥、凭据或画板内容。

## 后果

断网、中继故障或配置错误只让反馈给出明确失败结局，不影响本机作品。部署与运维按 [构建说明](../../packaging/README.md) 交接；产品版本与用户可见能力按 ADR 0024 在同一份更新说明里记录。

## 2026-11-22：token 归属

- 提交反馈的用户自带 Gitea token，权限限于对 `kacha-feedback` 仓库建 issue、写评论/标签与上传附件。
- 反馈中继只在本次请求里转交 token，不保存、不缓存、不复用，也不写入日志、issue、附件或诊断包；服务端不持有统一写 token。
- 核心画板保持离线：打开、编辑、组织与打包画板都不依赖 token、登录或反馈中继。

## 2026-11-24：一键授权

- 用户可在反馈表单里通过 Gitea OAuth2 授权码与 PKCE 一键授权；token 仍是提交者用户自带的凭据，由用户本人同意授权后取得。
- token 只写入当前用户数据根下受 Windows DPAPI 保护的凭据文件，不进入页面、仓库、测试夹具、诊断包或客户端产物；用户可重新授权覆盖它。
- 页面只读取授权状态，不持有 token；发送时由 Go 侧把本机 token 随本次请求交给中继。中继仍不保存、不缓存、不复用，服务端不持有统一写 token，核心画板仍离线可用。
