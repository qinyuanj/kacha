# 反馈是可选的联网能力

Kacha 的画板核心保持单机优先：打开、编辑、组织和打包画板都不需要网络。反馈是用户主动发起的可选联网能力，不参与画板核心路径。

## 决定

- 用户从首屏「反馈」入口提交文字、可选截图与脱敏诊断包；桌面 Go 服务使用用户自带 token 直连 Gitea `kacha-feedback` 仓库，创建 issue、上传附件、回写链接并返回 issue 编号与链接。
- 一键授权使用 Gitea OAuth2 授权码与 PKCE。token 只写入当前用户数据根下受 Windows DPAPI 保护的凭据文件；React 页面只读取授权状态，发送时由 Go 侧读取 token 并直接用于 Gitea API 鉴权，不进入页面、仓库、测试夹具、诊断包或客户端产物。权限限于对 `kacha-feedback` 仓库建 issue、写评论/标签与上传附件。
- 不保留远端应用中继：客户端没有中继地址、统一服务端写 token 或中继回退。重复提交只在桌面本机内存中识别两分钟，token 及其哈希不持久化；原中继的按 IP 限流随服务一起删除。
- 不新增远端应用服务依赖：客户端启动、画板编辑与本机数据管理都不要求登录远端服务。Gitea 不可达、token 无效或权限不足只让反馈给出明确失败结局，核心画板继续离线可用。
- 反馈内容不进入画板、任务目录或画板包；诊断包沿用脱敏规则，不携带 API 密钥、网关密钥、凭据或画板内容。本机诊断包导出是独立能力，不依赖反馈发送。

## 后果

反馈直接受用户 Gitea 权限与网络可达性影响，不再由运维提供转发服务。旧 `feedback_relay_url` 设置在读取时丢弃，其他设置保留。既有中继服务、程序与发布资产的删除及旧版客户端影响见 [ADR 0029](0029-remove-feedback-relay.md)。
