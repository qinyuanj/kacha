# 数据位置迁移靠复制校验后原子切换记录，旧位置一直可用

数据根由客户端管理、一台电脑一份（ADR 0023）。#161 把「位置」也变成可管理的一项：高级设置里可以选一个新目录，把整份数据搬过去。

迁移由桌面壳的 Go 服务完成，顺序固定：先校验两端路径（必须是两个真实目录、互不包含、目标为空且可写），再把数据根里的普通文件逐份复制到目标并比对长度与 sha256，全部通过之后才改写数据根记录（`shell-data` 之外的 `shell-state.json`，含迁移前的旧位置）。页面只负责拦下会打架的操作、选目标、看一眼进度，不做任何搬字节的事。

几点后果：

- 旧位置在任何时刻都是完整可用的数据：复制、校验、写记录任何一步失败，记录仍指旧位置，目标里已写入的半份内容被清掉，不会出现「半完成的目标成为唯一数据来源」。
- 新位置在下次启动时用不了（目录被删、盘没挂上）就退回记录里的旧位置，而不是重建一个空目录把旧数据晾在一边。
- 页面里的数据根是启动时读的一次快照，换根之后必须重新载入：迁移只改服务侧的共享位置，界面状态里的绝对路径在重新载入前按旧根重映射一次。
- 凭据与画板身份不随迁移改变：API 密钥文件是数据根里的普通文件，跟着整份数据复制，受系统保护后的密文与路径无关；迁移不写密钥、不改画板身份。
- 不做本地发现的自动迁移，也不复制根目录之外的路径：节点上指向数据根外的参考图仍是绝对路径，迁移不会把它们搬进来（与 ADR 0023「数据迁入只通过画板包」一致）。
